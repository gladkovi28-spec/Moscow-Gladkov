# Техническое задание
## Десктопное приложение «Трекер привычек»

### 1. Введение

**Название проекта:** Habit Tracker (Трекер привычек).

**Назначение документа:** описать требования к разрабатываемому
приложению, его функции, структуру данных и этапы разработки.

**Заказчик:** учебный проект, выполняемый в рамках курса.

### 2. Назначение и цель разработки

**Назначение:** приложение помогает пользователю вырабатывать
регулярные привычки и наглядно видеть свой прогресс.

**Цель:** создать десктопное приложение, в котором пользователь
заводит привычки, ежедневно отмечает их выполнение и получает
статистику: серии «подряд», процент выполнения за месяц и
календарную сетку активности за 8 недель.

### 3. Целевая аудитория

Все, кто хочет выработать регулярные привычки: учащиеся, взрослые,
следящие за режимом дня. Требуется настольный компьютер с Windows
или Linux и установленным Python 3.10+.

### 4. Требования к функциям

#### 4.1. Обязательные функции

| № | Функция | Описание |
|---|---------|----------|
| 1 | Создание привычки | Имя (обязательное, непустое), описание, цвет, частота: ежедневно или N раз в неделю (N от 1 до 7) |
| 2 | Редактирование привычки | Изменение всех полей созданной привычки |
| 3 | Удаление привычки | С подтверждением; удаляются и все отметки |
| 4 | Отметка выполнения | За сегодня одним нажатием; повторное нажатие снимает отметку |
| 5 | Отметка за прошедший день | Через календарную сетку: клик по дню ставит или снимает отметку |
| 6 | Текущая серия | Число дней подряд, в которые привычка выполнена, до сегодня |
| 7 | Личный рекорд | Самая длинная серия за всю историю |
| 8 | Процент за месяц | Доля выполненных дней от прошедших дней текущего месяца |
| 9 | Статистика | Окно с таблицей по всем привычкам (процент, серия, рекорд) и графиком выполнения за месяц |
| 10 | Календарная сетка | Сетка за 8 недель в стиле GitHub: закрашенный квадрат — выполненный день, цвет — цвет привычки |
| 11 | Экспорт в CSV | Сохранение истории всех отметок (привычка, дата) в файл через диалог выбора места |
| 12 | Архивация | Скрытие привычки из основного списка без удаления истории; возврат из архива |

#### 4.2. Ограничения

- Привычка без имени не сохраняется: форма не закрывается,
  пока имя пустое.
- Цель для недельной частоты — целое число от 1 до 7.
- Отметки можно ставить только за сегодняшний или прошедший день.
- Удаление привычки требует подтверждения пользователя.
- Приложение не требует подключения к интернету: все данные
  хранятся локально.

### 5. База данных

#### 5.1. Выбор хранилища

Для хранения данных используется СУБД SQLite (встроенный модуль
Python `sqlite3`). Обоснование выбора:

- не требует установки и запуска отдельного сервера — вся база
  лежит в одном файле `habits.db`;
- создаётся и заполняется автоматически при первом запуске;
- объём данных учебного проекта мал (сотни–тысячи записей),
  SQLite полностью покрывает потребности;
- стандартный модуль Python, ничего дополнительно ставить не нужно.

Файл базы `habits.db` создаётся рядом с программой; он включён
в `.gitignore`, так как содержит личные данные пользователя
и генерируется заново при первом запуске.

#### 5.2. Схема базы данных

База состоит из двух таблиц.

**Таблица `habits`** — привычки:

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный номер привычки |
| name | TEXT | NOT NULL, UNIQUE | Название привычки |
| description | TEXT | DEFAULT '' | Описание |
| color | TEXT | DEFAULT '#4CAF50' | Цвет карточки в формате #RRGGBB |
| freq_type | TEXT | NOT NULL, CHECK (freq_type IN ('daily','weekly')) | Тип частоты |
| freq_target | INTEGER | CHECK (freq_target BETWEEN 1 AND 7) | Цель: раз в неделю (для weekly) |
| created_at | TEXT | NOT NULL | Дата создания, формат YYYY-MM-DD |
| archived | INTEGER | NOT NULL DEFAULT 0 | Признак архивации: 0 — активна, 1 — в архиве |

**Таблица `completions`** — отметки выполнения:

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный номер отметки |
| habit_id | INTEGER | NOT NULL, внешний ключ на habits(id) | Привычка, к которой относится отметка |
| date | TEXT | NOT NULL | Дата отметки, формат YYYY-MM-DD |

#### 5.3. Целостность данных

- **Внешний ключ** `completions.habit_id` ссылается на
  `habits.id` с каскадным удалением (`ON DELETE CASCADE`):
  при удалении привычки автоматически удаляются все её отметки —
  в базе не остаётся «осиротевших» записей.
- **Ограничение уникальности** `UNIQUE (habit_id, date)`:
  один и тот же день не может быть отмечен дважды. Повторное
  добавление отметки перехватывается приложением и означает
  снятие отметки.
- **CHECK-ограничения** не дают записать некорректные значения:
  частоту вне списка daily/weekly и цель вне диапазона 1–7.
- **Имя привычки уникально** — нельзя завести две одинаковые
  привычки.
- Приложение всегда работает с базой через транзакции:
  изменение либо сохраняется целиком, либо не применяется вовсе
  (например, сбой при экспорте не портит данные).

#### 5.4. Индексы

| Индекс | Таблица | Поля | Назначение |
|--------|---------|------|------------|
| idx_completions_habit_date | completions | habit_id, date | Быстрый поиск отметок конкретной привычки: серии, сетка, процент |
| idx_habits_archived | habits | archived | Быстрая выборка активных и архивных привычек |

#### 5.5. Перечень операций с базой (модуль database.py)

Все обращения к базе идут только через функции модуля
`database.py` — SQL-запросы не разбросаны по коду интерфейса.

**Привычки:**

| Функция | Операция | SQL |
|---------|----------|-----|
| create_habit | Добавить привычку | INSERT INTO habits |
| get_habit | Получить одну привычку по id | SELECT ... WHERE id = ? |
| get_all_habits | Список активных привычек | SELECT ... WHERE archived = 0 |
| get_archived_habits | Список архивных привычек | SELECT ... WHERE archived = 1 |
| update_habit | Изменить поля привычки | UPDATE habits SET ... |
| set_archived | Заархивировать / вернуть из архива | UPDATE habits SET archived = ? |
| delete_habit | Удалить привычку и её отметки | DELETE FROM habits WHERE id = ? (каскадно удалит completions) |

**Отметки:**

| Функция | Операция | SQL |
|---------|----------|-----|
| add_completion | Поставить отметку за день | INSERT OR IGNORE INTO completions |
| remove_completion | Снять отметку за день | DELETE FROM completions WHERE habit_id = ? AND date = ? |
| toggle_completion | Отметка «наоборот» (кнопка «сегодня») | SELECT → есть отметка? remove : add |
| get_completions | Все отметки привычки за период | SELECT ... WHERE habit_id = ? AND date BETWEEN ? AND ? |
| has_completion | Отмечен ли конкретный день | SELECT COUNT(*) ... |
| export_all | Полная история отметок для CSV | SELECT h.name, c.date FROM completions c JOIN habits h |

Все запросы выполняются с параметрами (`?`) — это исключает
SQL-инъекции при подстановке данных из полей ввода.

#### 5.6. Схема базы данных (диаграмма)

```
+--------------------+          +----------------------+
|      habits        |          |     completions      |
+--------------------+          +----------------------+
| id        (PK)     |<---------| habit_id   (FK)      |
| name      NOT NULL |  1    ∞  | id          (PK)     |
| description        |          | date        NOT NULL |
| color              |          +----------------------+
| freq_type          |          UNIQUE (habit_id, date)
| freq_target        |          ON DELETE CASCADE
| created_at         |
| archived           |
+--------------------+
```

Связь привычек и отметок — «один ко многим»: у одной привычки
много отметок, каждая отметка принадлежит ровно одной привычке.

### 6. Структура интерфейса

Главное окно состоит из двух панелей.

**Левая панель** — список привычек: карточки с цветным маркером,
названием и текущей серией; кнопки «Добавить», «Статистика»,
«Экспорт CSV»; галочка «Показывать архив».

**Правая панель** — детали выбранной привычки: название, описание,
частота, серия и рекорд, календарная сетка за 8 недель; кнопки
«Отметить сегодня», «Редактировать», «Архивировать», «Удалить».

Диалоги: создание/редактирование привычки (форма с валидацией
и выбором цвета), статистика (таблица и график), подтверждение
удаления, сохранение CSV.

### 7. Архитектура

Проект разделён на слои:

- `database.py` — единственный модуль, который знает про SQLite:
  схема, инициализация базы, все SQL-запросы из раздела 5.5;
- `stats.py` — расчёт серий и процентов; работает с данными,
  которые вернул `database.py`, сам базу не открывает;
- `ui/` — модули интерфейса на PyQt6: главное окно, диалоги,
  виджеты (карточка привычки, календарная сетка, окно статистики);
  вызывает функции `database.py` и `stats.py`;
- `main.py` — точка входа: инициализирует базу и запускает
  приложение.

Такое разделение упрощает тестирование логики отдельно от
интерфейса и замену SQLite на другую СУБД при необходимости.

### 10. Критерии готовности

Приложение считается готовым, если:

1. Можно создать, отредактировать, удалить и заархивировать
   привычку.
2. Отметка за день ставится и снимается, данные сохраняются
   после перезапуска.
3. Серия, рекорд и процент за месяц рассчитываются корректно.
4. Календарная сетка отражает реальные отметки за 8 недель.
5. Экспорт CSV создаёт файл, который открывается в Excel.
6. Сборка exe запускается на компьютере без установленного Python.
7. База данных создаётся автоматически, а удаление привычки
   не оставляет в ней висящих отметок.
